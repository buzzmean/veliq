# Интерфейс VELIQ для Windows

Приложение `VELIQ.exe` использует WPF и .NET 8. Оно работает без прав администратора
на Windows 10/11 x64. Перехват и маршрутизацию выполняет отдельная служба
`veliq-service.exe`; окно управляет ею через защищённый IPC.

## Сборка и запуск

Из корня репозитория с установленным .NET SDK 8:

```powershell
& .\tools\windows\build-desktop.ps1
& .\bin\release\VELIQ.exe
```

Результат сборки — `bin\release\VELIQ.exe` для Windows x64 со встроенной средой
.NET. Отдельная установка .NET Runtime на пользовательском ПК не нужна. Первый
запуск может распаковать нативные библиотеки во временный каталог пользователя.

Для сборки и проверки переносимой логики:

```powershell
dotnet build VELIQ.sln
dotnet test tests/desktop/Veliq.Client.Tests.csproj --nologo
```

Запускайте интерфейс от пользователя, чей SID разрешён установленной службой.
GUI не устанавливает драйвер и не запрашивает повышение прав. Для пользовательской
установки используйте [официальный установщик](https://veliqapp.ru/download).
Сценарии сборки и проверки службы описаны в
[инструкции Windows](../../docs/WINDOWS_REAL_E2E.md).

## Окно, трей и обновление

При обычном запуске открывается окно. Запуск с `--autostart` сразу создаёт значок
в трее и не раскрывает окно, независимо от прежнего значения настройки запуска
свёрнутым. Первый запуск после установки обрабатывается отдельно. Повторный
`--autostart` не раскрывает уже работающее окно; ручной запуск позволяет его открыть.

Крестик скрывает окно в трей. Открыть его снова или явно завершить приложение
можно через меню значка. Закрытие окна не отключает оптимизацию. Выход через меню
выполняет штатное завершение работы интерфейса и связанных с ним маршрутов.

Настройки интерфейса находятся в `%LOCALAPPDATA%\VELIQ\desktop.json`.
Автозапуск регистрируется для текущего пользователя в HKCU Run. Старое сохранённое
значение запуска свёрнутым читается для совместимости, но не отменяет поведение
`--autostart`.

Кнопка обновления рядом с логотипом появляется при наличии более новой версии.
Сбой установки не является подтверждением обновления. Доступ и настройки должны
сохраниться после штатного обновления; порядок подготовки и восстановления
описан в [документации установщика](../../docs/INSTALLER_NO_RESTART.md).

## Разделы приложения

- Главная показывает состояние оптимизации, маршрут, измерения и счётчики трафика.
- Сервисы показывают запущенные приложения, для которых подтверждено применение
  стратегии. Установленный профиль сам по себе не подтверждает активное соединение.
- Игры содержат настройки игровых профилей. Прямой маршрут и локальные стратегии
  не означают использование игрового релея.
- Диагностика показывает состояние службы, захвата, управляющего сервера и сети.
  MTU-проверка службы не определяет PMTU всего пути до игрового сервера.
- Настройки содержат доступ, автозапуск и доступные параметры приложения.
  Клубная активация не требует привязки к личному аккаунту.

Недоступная служба или IPC отображаются с объяснением и возможностью повторить
подключение. Устаревшие показатели очищаются. Отсутствующее измерение показывается
как «Нет данных»; его нельзя подменять нулевой задержкой.

## Архитектура и проверки

`apps/desktop-core` содержит модели, ресурсы и IPC-клиент без WPF и перехвата
трафика. `apps/desktop` отвечает за окно, трей, автозапуск, проверку службы и
единственный экземпляр приложения. Машинные данные и IPC-токен находятся в
защищённом `%ProgramData%\VELIQ`; пользовательские файлы разных SID не смешиваются.

Русские строки находятся в `apps/desktop-core/Resources/Strings.resx`.
Нейтральная культура — `ru-RU`. Системные диалоги Windows используют язык ОС;
имена выбранных приложений и технические идентификаторы сохраняют своё написание.

Тесты переносимой логики проверяют обмен IPC, таймауты, отмену, модели, команды,
обновление показателей и ресурсы. Проверки Windows запускают настоящее окно и
значок трея. Сборка на Linux не подтверждает поведение окна, вход в сеанс Windows
или работу WinDivert на пользовательском ПК. Эти результаты учитываются отдельно.
