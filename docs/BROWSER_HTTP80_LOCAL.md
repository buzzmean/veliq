# Ограниченный HTTP80 LOCAL

01.11.2026. Первый отдельный HTTP80-путь этапа R1. Он применяется только к
наблюдаемому HTTP Host известного DPI-origin в native browser AUTO, публичному
IPv4:80, текущим процессу/профилю/сети. Это собственная стратегия
`http80-host-split`; HTTP/QUIC-правила импортированного Flowseal-каталога остаются
unsupported. HTTPS TCP443 использует прежнюю независимую лестницу.

## Допуск и проверка

Холодное соединение остаётся на аутентифицированном RELAY. Параллельно служба
делает отдельный HEAD `/` через LOCAL: без пользовательских cookies,
Authorization, пути или тела. Только 301/302/307/308 с единственным Location
на HTTPS того же хоста, корневой путь без query/fragment/userinfo, и committed
transform witness этого сокета разрешают следующие HTTP80 LOCAL-соединения.
Перенаправление не выполняется; ответ 200 (в том числе страница блокировки),
чужой хост или отсутствие witness не дают допуска. Witness считывается до Close.

Это наблюдение неаутентифицированного HTTP-перехода, не TLS/CDN proof и не
доказательство загрузки страницы, полного body, доступности HTTPS или экономии
VPS. Активный посредник может подделать HTTP-ответ. Настройка защищённых доменов
не ослабляется: protected/RELAY-first, обычные сайты, explicit rules/baseline,
OFF/DIRECT, PAC, DNS hints/ambiguous origin, private IP и TLS исключены.
Host с портом, отличным от 80, не разрешает эту лестницу на TCP80.

Ключ допуска: network fingerprint, profile, policy revision, hostname,
destination IP:80, executable, PID и birth. TTL 5 минут, повтор после отказа
через 3 минуты, максимум 128 записей; неиспользуемые 30 минут записи удаляются.
Максимум одна HTTP80-проба, общий лимит браузерных проб 4, deadline 5 секунд,
ответ ограничен 8 KiB. Кеш только в памяти. Смена политики/сети или завершение
процесса проверяются перед открытием и публикацией результата; устаревший
результат не публикуется и освобождает свой retry. Более старый worker не может
перезаписать cooldown от нового отказа пользовательского соединения.

## Пакеты и соединения

Стратегия собирает первый HTTP/1.0 или HTTP/1.1 origin-form header до 8 KiB:
ровно один Host, без folded/неоднозначных заголовков, CONNECT или absolute-form.
Только браузерный TCP80-профиль с cutoff 1 и ограничением домена; фактический
Host проверяется даже при доверенных метаданных. Native ingress также отвергает
неоднозначный Host до выбора LOCAL. Обычный HTTP на другом порту сохраняет
свою маршрутизацию, но не получает HTTP80-допуск.

Исходные TCP-сегменты разделяются после первого символа Host без изменения
любого байта HTTP-запроса, cookies или тела. Сохраняются sequence, ACK, options,
PSH/CWR и корректные checksums; LSO разбивается на пакеты не более 1500 bytes,
максимум 64 выхода. Нет fake packets или повторной отправки запроса. Сборка
ограничена 32 KiB/32 сегментами/2 секундами; неподдерживаемый поток выпускается
без изменения. Следующие запросы keep-alive не трансформируются.

LOCAL dial ограничен 1 секундой. Только отказ до передачи пользовательских
байтов может выбрать RELAY для этого открытия. После возврата соединения
нет функции повторного dial и сохранённого запроса. Первый ответ ожидается
1,5 секунды, ожидание ответа после новых записей — до 6 секунд. Reset/write
failure/наблюдаемый stall отзывают допуск для будущих открытий на 3 минуты;
старые RELAY-соединения сохраняются. Обычный EOF после ответа не доказывает
полноту HTTP body: служба не разбирает тела пользовательских запросов/ответов.

Диагностика `browser.native.status.http80_local`: entries, active, attempts,
upgrades, failures, cancelled, local_opens, relay_opens. Без URL, cookies и body.

## Автоматическая проверка и пределы

Переносимые тесты проверяют все границы разбиения заголовка, обратный порядок
сегментов, LSO, byte identity/checksums, parser/scope, отдельный HEAD и отказ
при неподходящем ответе или отсутствующем witness.

`TestWindowsHTTP80ColdUpgradeAndFailure`: настоящий Windows PID/birth/path
изолированного тестового exe, настоящие TCP/HTTP и QUIC+mTLS relay с one-shot
ticket. Шесть вариантов: upgrade, missing-witness, foreign-redirect,
block-page, OFF→ON, возврат сети. Успешные варианты проверяют холодный RELAY,
новый LOCAL, настоящий TCP RST после частичного body, отсутствие replay,
cooldown и RELAY следующего запроса. Исходный RELAY остаётся работоспособным.
Отмена не публикует HTTP80-допуск; после восстановления новая проба разрешена.

Packet capture/injection — seam: настоящий localstrategy engine преобразует
синтетические IPv4/TCP пакеты, их payload проходит через loopback TCP. DNS/IP
mapping, network fingerprint, backend witness — seams. Это не Chromium,
WinDivert injection, owner SID/ACL, публичная сеть или реальная HTTP80-приёмка.
Отдельный CI исполняет native fixture и полный Windows Go race/vet/build плюс
pinned DLL filter compiler без открытия драйвера. Linux race/vet/build с PG17
проверяются workflow Relay на том же commit. R1 остаётся частично выполненным.
