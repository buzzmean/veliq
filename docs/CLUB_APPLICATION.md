# Заявки клуба

Форма website/clubs.html отправляет структурированное сообщение в существующий /api/v1/support/session, state, message. Требуется отдельно установленный support backend из 2bcb6d5771f47147c71cd056e6beb0eb68ad9336; эта ветка не включает его установку. Статические файлы main не являются актуальным снимком production — нельзя развёртывать весь website поверх действующего сайта.

Каждая заявка получает reference CL-<12 hex>. Все заполненные поля, согласие и источник попадают одним текстовым сообщением в support_messages и durable support_outbox; бот публикует сообщение в настроенной группе. Открытый диалог сохраняется, заявка добавляется в него с отдельным reference; при решённом диалоге создаётся новый. Ответ операторов доступен в обычном widget. Это форма обращения, без отдельного CRM-реестра.

Контактные данные не сохраняются в browser storage. После неопределённой сетевой ошибки повтор использует тот же ключ и тело, поля временно заблокированы до подтверждения. Сервер проверяет Origin, сессию, лимиты и длину текста. Проверки полей формы выполняются на клиенте; общий support API по-прежнему принимает обычные текстовые сообщения.

Чат: увеличенное окно, компактный composer, Enter отправляет, Shift+Enter переносит, IME composition не отправляет. Пояснения/завершение сессии доступны через «О чате», подтверждение внутри widget.

Проверка: `node --test tests/website/club-application.test.cjs`. Живую отправку проверять только вымышленными тестовыми данными в согласованную группу. При внедрении обновить версии script URL затронутых страниц. Генератор сайта не является каноническим источником действующего production HTML; не запускать его поверх поздних account/clean-URL изменений.
