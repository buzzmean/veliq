# Первое подключение VELIQ

На личной установке приложение сначала проверяет сохранённое подключение.
Подтверждённый аккаунт с действующей активацией открывает основное окно без
повторного входа. Новый ПК показывает отдельный стартовый экран: «Личный компьютер»
и «Клубный компьютер». Наличие установленного EXE само по себе не открывает окно
управления маршрутизацией.

Личный вход и регистрация выполняются в компактном окне приложения: почта,
код из письма, имя нового аккаунта, подтверждение компьютера. На экране виден
только текущий шаг. Браузер для личного входа не запускается.
`account.link.start` создаёт подписанный запрос устройства; приложение использует
существующий HTTPS account API и отдельную сессию cookie только в памяти.
Код очищается после попытки, сессия уничтожается при закрытии; после подтверждения
сохранённой identity управляет служба. До подтверждения службы основной экран
недоступен. Редиректы account API отклоняются, ответ ограничен 1 МиБ.
Личный кабинет по отдельной ссылке и подготовка клубного образа администратором
сохраняют свои существующие веб-сценарии.
Код вводится в маскированное поле, очищается перед отправкой через штатный
`activation.set` и не записывается в предпочтения или журналы интерфейса.
Сохранённая действующая активация старым кодом явно показывается как подключение
по коду, а не как личный аккаунт. Код не подменяет защищённую конфигурацию клуба:
управляемый клубный режим подготавливает администратор штатными средствами.
Игрокам уже подготовленного клуба личный вход не требуется.

Стартовый экран не заменяет проверок службы. Подписка, identity, разрешение
захвата, полномочия владельца и клубные ограничения проверяются прежними
механизмами. Клиентского флага «вошёл» нет. В ожидании подтверждения, при отзыве,
ошибке или неизвестном состоянии аккаунта переход недоступен. Кнопка продолжения
повторно запрашивает актуальное состояние.

## Аварийное отключение — только для клуба

У личного аккаунта нет аварийной кнопки, настройки аварийного пароля и этих
пунктов в трее. Обычные включение, отключение и выход остаются доступными.
`--club` не включает клубный интерфейс на личной установке.

Служба отклоняет `emergency.status`, `emergency.stop`, `emergency.finish` вне
защищённого клубного режима с `EMERGENCY_CLUB_ONLY`, до чтения пароля и очистки.
Известный аккаунт `player` блокирует эти команды даже при оставшейся клубной
конфигурации. Не читаемая/повреждённая запись роли не предоставляет право.
На подготовленном клубном ПК сохраняются отдельный аварийный пароль,
ограничение попыток, проверка владельца и подтверждение полного завершения.
Возможность клубного аварийного отключения до подключения к CP сохраняется.

Изменение не удаляет существующий verifier, не меняет identity, не выполняет
перезагрузок и не включает аварийное отключение во время проверки.

## Проверки

Переносимые тесты проверяют вход со свежей/сохранённой активацией, ожидание,
неизвестную роль, отзыв, истечение подписки и подготовленный образ. Native WPF
проверка загружает производственный XAML, проверяет размеры/маскировку поля,
ошибочный код, переход после подтверждения и сохраняет снимки трёх экранов.
Go-тесты проверяют прямой и owner IPC, отказ личному аккаунту до обработки
пароля и сохранение клубного сценария до сетевой инициализации.
Физический вход/регистрация с почтой и клубным кодом требуют отдельной приёмки;
автоматические проверки используют только фикстуры.
