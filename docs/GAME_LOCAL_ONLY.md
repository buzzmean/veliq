# Игровой UDP без relay: контракт и приёмка

Локальный режим для новых игровых UDP-подключений выбирается через
`gameudp.set`: `{"profile_id":"cs2","enabled":true,"local_only":true}`.
Это существующий защищённый IPC, а не команда для публичного API.
Кнопка «Локально» и включение игрового UDP-обхода передают этот флаг явно.
Старая служба, не знающая поле, должна отклонить запрос; повтор без флага запрещён.

## Контракт

- `local_only` сохраняется вместе с выбранным полным путём игры. Пропуск поля
  в последующих запросах сохраняет выбор; явное `false` разрешает прежнюю
  цепочку DIRECT → LOCAL → authenticated RELAY. Старые настройки без поля
  сохраняют прежнее поведение, интерфейс обозначает такую цепочку как «Авто».
- Политика охватывает выбранный точный executable, IPv4 UDP на публичный endpoint
  с портом >=1024. DNS, локальная сеть, TCP, другие программы и защищённые
  профили не получают новых разрешений. Это не системный запрет всего VPS-трафика.
- В local-only обучение ограничено сетью, executable, endpoint и политикой.
  Прежнее обучение RELAY не разрешает отправку через VPS. Подтверждённый
  DIRECT для точного endpoint можно использовать повторно.
- Потоки привязаны к PID, времени создания процесса и tuple. Смена настройки,
  обучения или исчерпание вариантов не перемещают открытый UDP-поток,
  не повторяют исходные пакеты и не начинают его first-flight заново.
  Старый relay-поток может продолжаться после выбора local-only; интерфейс
  предупреждает об этом. Нулевой relay проверяется после нового подключения.
- Неудача DIRECT разрешает ограниченные существующие локальные варианты только
  для следующих соединений. После последнего — `GAME_UDP_LOCAL_ONLY_EXHAUSTED`,
  без relay; новые потоки остаются DIRECT до окончания cooldown. Исчерпание
  сохраняется после перезапуска службы, в пределах TTL и ограниченного кэша.
- При недоступном capture/guard/network приманки не отправляются. Local-only
  не проваливается в автоматический relay; исходные пакеты идут DIRECT.
  Anti-cheat, конфликты перехватчиков и общие лимиты приманок сохранены.
- Устойчивость требует прежних ≥6 ответов в ≥3 секундных интервалах, span ≥2с
  и продолжающегося TX. Это транспортная оценка, не доказательство загрузки матча.
  Шесть ответов за 0.387с с последующим TX без RX не подтверждают успех.
- Выбор «Напрямую»/«Авто» в каталоге отключает явный игровой UDP-обход.
  Ручной профиль RELAY имеет приоритет как отдельный явный выбор маршрута.

Новый формат `game-udp.json` содержит дополнительное поле. При откате на старую
службу её строгий parser может отклонить такой файл. Перед разрешённой установкой
сохранить исходный файл и восстанавливать его вместе с соответствующим клиентом;
не удалять настройки или поле автоматически. В обычной diskless-сессии локальная
копия не переживёт перезагрузку.

## Что проверяют автоматические регрессии

Запрет relay при binding, полный цикл исчерпания и восстановление из сохранённого
обучения, старое relay-обучение и наблюдения старого потока, изоляция endpoint,
сохранение здорового DIRECT, отсутствие перехода в AUTO при недоступных guards,
сохранение настройки и откат при ошибке записи, IPC-диспетчер и сообщения GUI.
Сценарий CS2 — синтетическая регрессия по числу пакетов/диапазону времени из отчёта,
не воспроизведение оригинального PCAP или восстановленного Windows JSON fixture.
Причина сбоя (DPI, сервер или маршрут) этим не устанавливается.

## Физическая приёмка — пока НЕ ВЫПОЛНЕНА

**Запрещены reboot/shutdown/reset/sleep/logoff, смена технического режима,
автоматические перезапуски установщика, отключение NIC/LAN/iSCSI и перезапуск
браузеров. Ни один диск обычной пользовательской сессии не постоянен.**

Этот список не поручает запуск установки или изменение текущего ПК.
После отдельного согласования конкретного кандидата и его установки без reboot:

1. Зафиксировать реальные build/source/SHA256 GUI и службы. Подтвердить сохранение
   владельца/активации без вывода секретов. Старый Build577 не считать кандидатом.
2. Снять исходные игровые route/relay bytes; выбрать CS2 «Локально», проверить
   `engine.local_only=true`, состояние guards и точный executable/PID/birth.
3. Отключиться только от игрового сервера и выполнить новое подключение к
   `51.38.142.176:27015` (если сервер по-прежнему доступен). ОС, службу и браузеры
   не перезапускать. Если новый tuple не возник, first-flight тест не засчитывать.
4. Одновременно подтвердить вход в карту, устойчивую реальную игру минимум 10мин,
   свежие ответы, маршрут DIRECT/LOCAL_UDP и **нулевой прирост relay bytes игры**.
   Общий VELIQ ACTIVE, ping/A2S, ConnectOK и суммарные счётчики других приложений
   не являются PASS. Не объявлять процент потерь по отношению количества TX/RX.
5. При остановке ответов сохранить диагностические метаданные текущего потока
   без секретов. Следующая локальная стратегия — только новое игровое соединение.
   Исчерпание должно отображаться без скрытого перехода на VPS.
6. Отдельно согласовать аварийное отключение: неверный пароль ничего не меняет;
   правильный запускает восстановление только собственных настроек, подтверждение
   cleanup предшествует выходу; SCM/watchdog не поднимают службу обратно.
   Недоступность CP моделировать на изолированном стенде, не отключением сети клуба.
   Поведение уже открытых браузеров наблюдать отдельно, refresh policy не считать PASS.

Без физической Windows/ISP/anti-cheat/SCM-приёмки выпуск на 5–6 ПК не одобрен.
Freeze/reboot/payment gates остаются отдельными. Этот клиент основан на emergency
`d8887376`; ветка не содержит последующее обновление чистых URL сайта `50a881ee`.
Её website/CP не развёртывать поверх действующих серверов.
