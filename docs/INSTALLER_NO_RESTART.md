# Установка без перезагрузки Windows

Setup не закрывает браузеры и не перезапускает Windows. Установку и удаление
разрешено начинать только с `/NORESTART`; без него Setup завершается до изменений.
Параметры `/CLOSEAPPLICATIONS`, `/FORCECLOSEAPPLICATIONS` и `/RESTARTAPPLICATIONS`
отклоняются. Это относится и к `/UPDATE=1`. Обычный запуск без параметров не
начинает установку и показывает причину отказа.

Перед копированием файлов выполняется проверка только чтением. Занятый GUI или
файл заменяемого payload останавливает установку до `[InstallDelete]` и изменений
службы. Нужно отдельно завершить только VELIQ под её владельцем; Chrome/Edge
остаются открыты. Setup не ждёт фиксированные две секунды и не переносит замену
GUI на следующую загрузку: флаг `restartreplace` удалён. Если файл заняли после
проверки, копирование должно завершиться ошибкой, а не отложенной заменой.

Проверяются признаки незавершённых операций Windows: CBS `RebootPending`, Windows
Update `RebootRequired`, обе очереди `PendingFileRenameOperations`, ненулевой
`UpdateExeVolatile` и ожидающая смена имени компьютера. Эти значения не меняются,
не очищаются и не выводятся. Если чтение не удалось, результат неизвестен и
установка также отклоняется. Проверки не вызывают перезагрузку и не предлагают её.
Это снимок перечисленных признаков, а не обещание, что сторонняя программа не
потребует перезагрузку позднее.

Отдельно распознаётся служебная уборка Inno: пара удаления `_unins.tmp` и его
каталога `iu-*.tmp` непосредственно в известном TEMP, без других файлов и reparse
points. PE metadata должна принадлежать VELIQ Setup/Uninstall; если установленный
`unins000.exe` ещё существует, SHA256 клона должен совпадать с ним. Inno ставит
эту пару в очередь ещё до `InitializeUninstall`; она не меняет рабочие файлы и не
требует перезагрузки для работы приложения. Она учитывается отдельно в
`deferred_cleanup_count`. Реестр не очищается. Любая замена, неполная пара, чужой
файл, несовпадение хеша либо нераспознанная операция остаются блокирующими.
Поддерживаются обычный NT путь и наблюдавшиеся на Windows-runner префиксы
`*1`/`*2`; неизвестный префикс не даёт исключения.
Источник поведения: [Inno 6.4.3 RunFirstPhase](https://github.com/jrsoftware/issrc/blob/is-6_4_3/Projects/Src/Setup.Uninstall.pas).

После установки проверяются SHA256 **реально установленного** `{app}\VELIQ.exe`
и `%ProgramData%\VELIQ\veliq-service.exe` относительно проверенного payload.
Одного существования GUI недостаточно. Затем повторно читается состояние reboot.
`install-success.json` появляется только при совпадении обоих хешей, работающей
службе (либо предусмотренном остановленном состоянии клубного образа) и известном
отсутствии pending reboot. В отчёте есть `gui_sha256`, `service_sha256`, время,
`reboot_check_known`, `reboot_required` и безопасные коды `reboot_reasons`.

При ошибке `install-result.json` содержит FAIL, success marker удаляется.
`reboot_required=true` означает обнаруженный признак; `null` вместе с
`reboot_check_known=false` означает, что проверка недоступна. Оба состояния запрещают
PASS. Ошибка хеша не исправляется перезагрузкой.

Для автоматизации любой ненулевой exit code означает незавершённую установку:
1 — отказ инициализации/контрактов, 7 — отказ собственного preflight, 8 — ранний
отказ Inno из-за уже ожидающих замены файлов. Дополнительный
`/RESTARTEXITCODE=3010` допустим как защита для внешнего запуска с `/NORESTART`;
3010 нельзя считать PASS или разрешением перезагрузить ПК. 1641 — инцидент.
Автообновление сохраняет `/NORESTART`; его detached launcher не является
подтверждением завершения — требуются свежий отчёт и фактические хеши.

Проверки: `installer-safety-checks.ps1` в PS5.1/PS7 используют синтетический reader
реестра, реальные временные файлы/хеши и блокирующий handle. На одноразовом
Windows Actions runner `beta-installer-smoke.ps1` проверяет реальный Setup:
отказ без `/NORESTART`, занятый GUI в обычном и UPDATE режиме без смены PID/байтов,
отказ при несовпадении установленного GUI, install/update/uninstall и аккаунтный
образ. Production Setup с рабочим public CA только собирается, не запускается.

Если на тестовом ПК запрещены reboot/shutdown/logoff, запрет действует также на
дочерние скрипты и задачи. Freeze/seal/проверки после reboot остаются NOT_RUN.
Локальные копии на дисках обычной diskless-сессии не являются постоянным backup.
