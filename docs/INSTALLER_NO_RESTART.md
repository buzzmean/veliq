# Установка и обновление без перезагрузки

Обычный Setup запускается двойным щелчком. Политика Inno 6.4.3 выбирает и блокирует
«не перезагружать» на страницах подготовки и завершения. AlwaysRestart=no,
RestartIfNeededByRun=no, CloseApplications=no, RestartApplications=no. Отложенная
замена файлов не используется. Глобальные признаки ожидающей перезагрузки не меняются.

Штатный updater сам передаёт /NORESTART /NOCLOSEAPPLICATIONS /UPDATE=1. Пользователь
не вводит параметры. Тихие сторонние вызовы должны передавать /NORESTART: Inno
в этом режиме не использует выбор мастера. Опасные параметры закрытия приложений
и /LOADINF отклоняются. Удаление сохраняет отдельную прежнюю политику /NORESTART.
NeedRestart не переопределяется для маскировки ошибок; PrepareToInstall не сбрасывает
NeedsRestart. Проверенная подготовка возвращает конкретную причину отказа.

## Ожидающие операции Windows

Get-VeliqInstallRebootState читает обе очереди PendingFileRenameOperations,
признаки CBS/Windows Update/UpdateExeVolatile/переименования компьютера и DeleteFlag
служб VELIQ/neexitlag. Windows_pending и блокировка данного пакета — разные поля.

Операции, затрагивающие source или destination внутри каталога приложения,
ProgramData/VELIQ, прежнего ProgramData/neexitlag, их родительские каталоги или
системные WinDivert DLL/SYS, блокируют замену. Нечитаемые/неоднозначные/непарные
записи тоже блокируют. Обрабатываются NT-префиксы, существующие короткие пути;
reparse points в пути запрещены. Сторонняя операция вне этих областей записывается
как посторонняя. Для self-contained .NET и неизменного закреплённого WinDivert сам
по себе Windows Update pending не доказывает необходимость reboot для VELIQ.
Фактическая доступность файлов, SCM, драйвера и IPC проверяется отдельно.

Глобальный старый Get-VeliqRebootState оставлен как строгий диагностический аудит
и для его собственных регрессий; он не определяет допуск нового пакета. Исключения
NVIDIA/Edge/Gaming Services в этом аудите не являются разрешением чистить очередь.
Ни одна из функций не удаляет и не переписывает системные признаки reboot.

## Подготовка, подтверждение и восстановление

До InstallDelete новый transaction.ps1 проверяет область pending операций и SCM,
посылает команду штатного выхода GUI через SID/session pipe только процессам с
проверенным путём, ждёт выхода GUI/recovery helper, проверяет файлы на блокировки.
Совпадение имени процесса не разрешает его завершение. Браузеры не затрагиваются.
Для повторной подготовки в том же мастере создаётся новый каталог транзакции.

Предыдущие payload, service EXE/ACL/start mode, данные удаления, запись удаления
и ярлыки сохраняются в каталоге транзакции с доступом SYSTEM/Administrators.
Update-service блокирует повторный запуск службы на время замены, останавливает
принадлежащий watchdog и ждёт выхода его процесса. После замены проверяет IPC.
Драйверы закреплены по прежним SHA256; новый драйвер в этой задаче не добавляется.

Install-package подтверждает SCM, GUI/service SHA256, установленные DLL/SYS и IPC.
Ошибка backend при разрешённом захвате блокирует подтверждение. Для чистой
неактивированной установки отсутствие захвата нормально: активация выполняется
после входа пользователя. Перед итоговым PASS повторяется scoped pending check.
Успешный маркер не означает проверенную внешнюю маршрутизацию сайтов или игр.

При сбое восстанавливается предыдущий пакет и служба; пользовательские настройки,
identity и IPC token не ротируются. Ранее открытый GUI возобновляется под своим
SID с ограниченными правами через одноразовую задачу, без триггера загрузки Windows.
Невозможность восстановления даёт отдельный код; backup и диагностика сохраняются.
Мастер не показывает «установлено», если подтверждение не завершилось.

Состояния различаются: завершено; завершено с требованием reboot компонента;
заблокировано до reboot; обычная ошибка. В текущем пакете нет MSI, внешнего .NET
установщика или дочернего драйверного Setup, возвращающего «завершено, нужен reboot».
Нельзя выдавать за это состояние старый код3010 от preflight: он означал отказ до
копирования. Внутренний новый код20 означает блокировку подготовки; Inno возвращает
собственный код7. Ошибка пакета/подтверждения даёт ненулевой код, без success marker.
Коды MSI3010/1641 не являются кодами успешной установки этого пакета.

## Журналы и воспроизводимые проверки

SetupLogging=yes автоматически включает журнал Inno. Отдельный JSONL располагается
в ProgramData/VELIQ-Setup/Logs. Он содержит этапы, commit, pending операции и их связь,
занятый файл, результаты shutdown/rollback/IPC, без токенов и содержимого конфигурации.
Сообщения отказа указывают JSONL и журнал Inno. install-result.json содержит статус,
этап, безопасный код и независимые windows_reboot_pending/reboot_required.

Регрессии: installer-safety-checks.ps1, installer-scope-checks.ps1,
installer-package-checks.ps1, installer-transaction-files-checks.ps1 в PS5.1/7.
Последний тест меняет только workspace fixture при отсутствующей VELIQ; SCM,
системные очереди, задачи и ярлыки не меняет. installer-session-policy-checks.ps1
проверяет настоящий инертный Inno; локальный запуск требует AllowLocalInertFixture.
Полный beta-installer-smoke.ps1 разрешён только на disposable Windows Actions VM.
Он отдельно проверяет чистую установку, update, реальные удерживаемые файлы,
ошибку запуска службы с восстановлением/повтором, удаление и аккаунтный образ.
Это не заменяет Windows10/11, реальную активированную учётную запись и обычный
запуск через updater на пользовательском ПК. Эти результаты указываются отдельно.

Перезагрузки, выключение, logoff, смена diskless-режима и закрытие браузеров запрещены
также при тестах. Локальный backup одноразовой сессии не является постоянным хранением.
