# Обновление по кнопке

Начиная со сборки с этим изменением, служба проверяет Latest и скачивает подписанное обновление в фоне. После проверки подписи, размера и SHA-256 состояние становится `READY`. Таймер, повторное скачивание, открытие GUI и перезапуск службы не запускают Setup.

Кнопка внизу боковой панели показывает круговой прогресс скачивания. Готовый пакет устанавливается только по нажатию; подсказка содержит версию и предупреждение о кратком прерывании соединений VELIQ. Ошибку скачивания можно повторить, ошибку установки — повторить отдельным нажатием. Двойной запуск блокируется службой и GUI.

`update.status` возвращает прежние поля и `downloaded_bytes`/`total_bytes`. Авторизованный `update.install` принимает `{ "build": 123 }`: это версия, которую пользователь видел при нажатии. Смена кандидата требует нового нажатия. Перед запуском повторно проверяются размер и SHA-256. `update.retry` повторяет только проверку и скачивание. Клубная read-only политика не разрешает эти методы; наличие club-mode.json также блокирует установку непосредственно в updater.

Setup работает с прежними `/NORESTART /NOCLOSEAPPLICATIONS /UPDATE=1`. Код установщика, сохранение настроек и авторизации не изменены. Если Setup завершился, а старая служба продолжает работать, UI показывает ошибку установки вместо бесконечного ожидания. Выход GUI не считается согласием. После перезапуска службы кандидат снова проверяется по подписанному Latest; уже скачанный файл используется после сверки хеша. До получения метаданных доступность кешированного пакета не заявляется.

Установленная старая версия продолжает использовать свою прежнюю политику до обновления на версию с этим изменением. Публикация новой версии сама по себе не меняет поведение старого updater.
