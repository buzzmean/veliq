# Обновление по кнопке

На личных установках служба проверяет Latest и скачивает подписанное обновление в фоне. После проверки подписи, размера и SHA-256 состояние становится `READY`. Таймер, повторное скачивание, открытие GUI и перезапуск службы не запускают Setup. Для управляемого клубного режима действует отдельная политика ниже.

Кнопка внизу боковой панели показывает круговой прогресс скачивания. Готовый пакет устанавливается только по нажатию; подсказка содержит версию и предупреждение о кратком прерывании соединений VELIQ. Ошибку скачивания можно повторить, ошибку установки — повторить отдельным нажатием. Двойной запуск блокируется службой и GUI.

`update.status` возвращает прежние поля и `downloaded_bytes`/`total_bytes`. Авторизованный `update.install` принимает `{ "build": 123 }`: это версия, которую пользователь видел при нажатии. Смена кандидата требует нового нажатия. Перед запуском повторно проверяются размер и SHA-256. `update.retry` повторяет проверку и скачивание. Клубная read-only политика не разрешает эти методы; клубный пользователь не может запустить Setup даже при включённой администратором фоновой установке.

## Клубное фоновое обновление

Администратор один раз включает политику на ПК с новой версией updater, в **64-битной повышенной PowerShell** из папки установленного пакета:

```powershell
& .\tools\windows\Set-ClubUpdatePolicy.ps1 -Enabled $true
```

Она хранится в 64-битном `HKLM\SOFTWARE\VELIQ\ClubUpdates`: `Version=1` и `AutoInstall=1` (DWORD). Updater проверяет владельца SYSTEM/Administrators и защищённый DACL только для этих двух субъектов. Неверная схема, пользовательский владелец или лишние разрешения не дают права установки. Команда с `-Enabled $false` отзывает разрешение без перезапуска службы; уже начатый Setup безопасно завершает свою транзакцию.

Политика применяется только к клубной установке, обнаруженной службой или по `club-mode.json`. Сам файл клуба не даёт разрешения на обновление; наличие политики на личном ПК не превращает его в клубный. Политика выключена по умолчанию. Гостевые IPC-права не расширяются.

Проверка после запуска начинается через 60–90 секунд, затем раз в шесть часов; ошибки метаданных и загрузки повторяются через три минуты. Загрузка в managed-режиме ограничена 2 МиБ/с с начальным допуском 64 КиБ; глобального ограничения на весь клуб и LAN-кэша в этой версии нет. Клубный кэш остаётся необязательным будущим улучшением.

После получения официального Latest, проверки Ed25519, размера и SHA-256 служба повторно читает разрешение, фиксирует единственную попытку этой сборки и запускает прежний silent Setup. Активная сессия LANGAME и вход гостя не задерживаются. Во время замены службы возможен короткий перерыв обслуживаемых VELIQ соединений; пять секунд не гарантируются. Перезагрузка ПК, закрытие игр и браузеров не требуются. Фоновый Setup возвращает ранее работающий GUI в трей через `--autostart` в правильной пользовательской сессии.

Маркер `updates\auto-install-<build>.attempt` предотвращает цикл переустановок этой же сборки после неудачи, отката или перезапуска службы. Он сохраняется и при ошибке запуска Setup; такой сбой требует проверки администратором, следующая более новая сборка имеет собственную попытку. Updater не удаляет маркер автоматически, не перезапускает ОС и не скрывает `UPDATE_AUTO_ATTEMPT_RECORDED`/`UPDATE_LAUNCH_FAILED`. История попыток не сбрасывает журнал потерь или права устройства.

На diskless-ПК политика и новый updater должны попасть в постоянный образ или поддерживаемый клубный bootstrap один раз. Включение в обычной непостоянной сессии не изменяет базовый образ. Это не повод автоматически включать технический режим или перезагружать ПК.

Setup работает с прежними `/NORESTART /NOCLOSEAPPLICATIONS /UPDATE=1`. Код установщика, сохранение настроек и авторизации не изменены. Если Setup завершился, а старая служба продолжает работать, UI показывает ошибку установки вместо бесконечного ожидания. Выход GUI не считается согласием. После перезапуска службы кандидат снова проверяется по подписанному Latest; уже скачанный файл используется после сверки хеша. До получения метаданных доступность кешированного пакета не заявляется.

Установленная старая версия продолжает использовать свою прежнюю политику до обновления на версию с этим изменением. Публикация новой версии сама по себе не меняет поведение старого updater.

## Панель задач и трей

Для новых настроек «Сворачивать в трей» выключено. Значок трея существует всё время работы GUI независимо от этой опции. При выключенной опции обычное сворачивание сохраняет окно на панели задач; при включённой пользователь явно выбирает скрытие окна в трей. Явно сохранённый выбор не сбрасывается. Полный выход из GUI удаляет значок трея.
