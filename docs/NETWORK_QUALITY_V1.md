# Качество сети: первое поколение измерений

Измеритель оценивает путь до настроенной авторизованной контрольной цели. Её задержка не является задержкой до любого игрового сервера. Работа этой функции не доказывает снижение потерь на реальном ПК. Для игр разрешены только прямой путь и локальные стратегии.

## Окно наблюдений

История маршрута охватывает 60 секунд, не более 128 раундов и 64 маршрутов. Стандартный раунд содержит пять проб. Для участия в AUTO нужны не менее 20 действительно отправленных сетевых проб и трёх разных раундов. Переключение требует трёх свежих парных наблюдений текущего и нового маршрутов; повторное чтение одного результата интерфейсом не считается новым наблюдением.

При интервале пять секунд данные накапливаются десятки секунд. Даже 50–60 проб в минуту дают грубую оценку потерь: показывается размер выборки, а 0% не означает отсутствие потерь в интернете.

В службе сохраняются времена отправки, RTT проверенного ответа и исходы. В каждую строку IPC не копируются все пакеты. Сводка включает последний успешный RTT, медиану, ближайший ранг p95, среднюю абсолютную разность соседних RTT как джиттер, долю безответных отправленных проб, EWMA, последовательные потери, максимальную серию, локальные ошибки, стабильность и количество измерений.

Коэффициент EWMA — 0,25 на раунд; значение пересчитывается из оставшегося окна, поэтому устаревшее наблюдение не остаётся навсегда. Старые агрегаты не доказывают перцентили: `percentiles_available=false`, медиана и p95 не выдумываются. Медиана средних по раундам используется только как совместимый резерв оценки.

Отмена родительской операции не записывается сетевым таймаутом. Таймаут означает отсутствие пригодного сквозного ответа, но не определяет повреждённый участок. Известные локальные ошибки считаются отдельно. Из потерь проб нельзя вычитать накопительные отбросы общих очередей: в них есть другой трафик.

## Оценка и подтверждение

Для пригодного маршрута вычисляется оценка в условных миллисекундах:

```text
0.90 * median RTT + 0.10 * EWMA RTT
+ 0.50 * max(0, p95 RTT - median RTT)
+ 2 * rolling jitter
+ 4000 * rolling probe loss
+ 2000 * failure rate
+ 25 * max(0, largest loss burst - 1)
+ 15 * relay load
+ 20 * (1 - stability)
```

RTT и джиттер заданы в миллисекундах. Один процентный пункт устойчивых потерь добавляет 40 единиц, серия из пяти потерь — ещё 100. Поэтому путь 55 мс / 0% / 2 мс предпочтительнее пути 48 мс / 2% / 7 мс, а 58 мс / 0,1% / 3 мс — лучше 80 мс / 1,5% / 12 мс. Это инженерные параметры, а не подтверждённая оценка качества каждой игры.

Индекс стабильности:

```text
1 / (1 + 10*loss + jitter/50ms + 0.1*max(0, burst-1))
```

Он не является вероятностью доступности и не скрывает наблюдаемые потери.

Совместимые параметры выбора: улучшение минимум на 5 единиц, время текущего маршрута минимум 30 секунд, подтверждение 10 секунд. Для продолжения подтверждения нужны новые данные обоих путей. Один плохой раунд виден, но не доказывает устойчивое ухудшение. Равные оценки разрешаются детерминированно по идентификатору. Неизвестный прямой путь не доказывает преимущество релея.

Ускоренная реакция применяется при завершении сессии, ошибке открытия/отправки/приёма пробы, трёх безответных пробах подряд, серии из пяти потерь через границы раундов либо потерях не менее 10% при минимум 40 образцах и двух плохих раундах. Восстановление требует трёх хороших раундов на протяжении минимум 10 секунд. Позднее закрытие старого поколения транспорта не ухудшает новое. Готовый результат публикуется без ожидания самого медленного маршрута.

## Действующие потоки

Выбор и резервные варианты относятся к новым потокам. После закрепления TCP/UDP больше не запрашивают AUTO. Резерв можно попробовать при открытии до отправки данных приложения. Изменение качества не переносит действующую игру.

При фактической ошибке ввода-вывода политика может отправить ещё не переданные пакеты разрешённым прямым путём либо заблокировать их. Защищённое назначение прямого резерва не получает. Смена внешнего адреса может разорвать сессию приложения и не является бесшовной. Принятые QUIC данные эта функция повторно не отправляет.

## Разделение потерь

| Метрика | Наблюдение и смысл |
|---|---|
| `probe_loss` | Отправленная проба без проверенного ответа; участок отказа неизвестен |
| `capture_processing_drops` | Локальный отказ проверки размера или обработки |
| `capture_queue_drops` | Переполнение очереди потока в пользовательской части захвата |
| `worker_saturation_drops` | Реальный отброс при исчерпании обработчиков и политике блокировки; разрешённая прямая отправка потерей не считается |
| `capture_receive_errors` | События ошибки получения WinDivert; число пакетов не выдумывается |
| `capture_kernel_queue_drops` | Через этот API недоступно |
| `transport_queue_drops` | Переполнение локальной очереди ответов QUIC по потоку |
| `quic_decode_drops`, `unknown_flow_drops` | Ошибка протокола или неизвестный поток при разборе датаграмм |
| `relay_socket_send_drops` | Ошибка локальной отправки; получение другой стороной не доказано |
| `reply_reinjection_failures` | Не удалось вернуть ответ в стек Windows |
| `policy_drops` | Намеренная блокировка или ограничение релея, а не доказанная потеря сети |

Для метрики указываются количество, попытки и доступность. Без попыток нет процента. Накопительные счётчики компонента нельзя делить на число проб скользящего окна. `quality.diagnostics` требует авторизации владельца. Счётчики релея доступны через его приватные метрики; интерфейс не выдумывает удалённые значения. Неизмеренные внутренние отбросы QUIC и ядра нельзя объявлять нулевыми.

## Дальнейшее развитие и проверки

[Качество конкретной цели и FEC](design/DESTINATION_QUALITY_AND_FEC.md) — отдельные контракты. Метаданные потока не дают автоматически RTT или потери игры. Произвольное сканирование интернета и фиксированный список игровых IP не добавляются.

Нужны детерминированные тесты качества, серий потерь, состояния, выбора, переполнений и закрепления, реальный эхо-обмен, проверка гонок, интерфейса и Windows. Измерения качества игры на реальном маршруте выполняются отдельно.

Ошибка отправки или открытия UDP немедленно сообщает о состоянии текущего поколения транспорта. Отмена и чрезмерный размер локальной датаграммы не считаются отказом релея. Таймаут уже отправленной пробы остаётся потерей пробы; ошибка самой отправки — локальной или транспортной ошибкой.
