# Повторы личной оплаты

Обычный личный заказ без промокода сохраняется до обращения к платёжному
провайдеру. В транзакции фиксируются сумма в копейках, срок, число мест,
подписка и ключ повтора. Только запрос, создавший эту запись, может один раз
вызвать создание оплаты. SQL-транзакция во время сетевого запроса не удерживается.

`POST /api/v1/account/subscriptions/{id}/quote` сохраняет прежний контракт.
Для `POST /api/v1/account/subscriptions/{id}/pay` нужны:

```json
{"months":1,"expected_amount_kopecks":39900,"idempotency_key":"01234567-89ab-4cde-8fab-0123456789ab","auto_renew":false}
```

Ключ содержит 16–96 латинских букв, цифр, `_` или `-`. Кабинет создаёт его один
раз для подтверждённого заказа и сохраняет вместе с запросом до определённого
результата. Повтор, в том числе после сетевой ошибки, использует тот же ключ.
`quote_version` для обычного личного заказа не требуется. Клубная оплата и
проверка промокода сохраняют отдельные действующие контракты. Создание обычного
заказа и owner-test заказа взаимно проверяет незавершённые личные оплаты под
одной блокировкой аккаунта; промокод не обходит неопределённый результат
обычной оплаты. Расчёт без создания заказа не занимает резерв и не меняется.

Ответ `200` содержит `id` локального заказа/платежа, `status`, `review_required`,
зафиксированный `quote` и, только для пригодного к оплате pending-заказа,
`redirect`. Успешный повтор возвращает тот же ID и сохранённую ссылку.
При `status=succeeded` ссылки нет: кабинет обновляет сведения, новую оплату
не создаёт. Смена конфигурации тарифа не меняет сохранённый заказ.

Ошибки:

- `400 PAYMENT_IDEMPOTENCY_REQUIRED`: нет корректного ключа; обновить кабинет.
- `409 PAYMENT_CONFIRMATION_REQUIRED`: не подтверждена сумма из расчёта.
- `409 PAYMENT_IDEMPOTENCY_CONFLICT`: прежний ключ использован с другой
  подпиской, суммой или сроком; такой запрос не создаёт оплату.
- `409 PAYMENT_PRICE_CHANGED`: новая оплата не соответствует текущей цене.
- `409 PAYMENT_IN_PROGRESS`: у аккаунта уже есть незавершённый личный заказ
  или требующая сверки старая оплата; другой ключ не обходит ограничение.
- `409/503 PAYMENT_RECONCILIATION_REQUIRED`: результат обращения к провайдеру
  либо сохранения ответа неопределён. Не повторять создание с новым ключом.

Потеря ответа, отмена HTTP-запроса и перезапуск сервера не освобождают запись.
Даже отменённая провайдером ссылка может подтвердиться позже. Неопределённый
заказ сверяется через существующий защищённый операторский endpoint
`POST /api/v1/admin/promotions/reconcile`: сервер сам проверяет providerID,
подписку и сумму у провайдера. Это не запускает новую оплату и не выполняет
возврат. При сверке без ссылки прежний pending-заказ не получает новую ссылку
автоматически; последующий подтверждённый платёж зачисляется один раз.

Добавочная миграция 14 создаёт только журнал личных заказов, индексы и защиту
неизменности условий. Существующие платежи, сроки доступа, бессрочные права,
устройства и активации не переписываются. Она не очищает тестовые данные и
не классифицирует суммы 3,99 ₽ или отменённые оплаты как мусор. Сначала
обновляется сервер, затем кабинет; старая вкладка без ключа получит явную ошибку.
