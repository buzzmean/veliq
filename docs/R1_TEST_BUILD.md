# Тестовая служба R1 для Windows x64

Workflow **YouTube LOCAL** публикует артефакт `VELIQ-R1-service-win-x64`
после Windows Go race, vet/build, холодного сценария CDN и проверки фильтров
на закреплённой WinDivert DLL. Вкладка **Actions → YouTube LOCAL → успешный
запуск → Artifacts** содержит ZIP. Выбирайте запуск по точному SHA нужного PR.
В PR собирается его head, а не временный merge-коммит GitHub.

Архив содержит только `veliq-service.exe`, `manifest.json`, `build-info.txt`,
`SHA256SUMS` и этот README. Это неподписанная тестовая служба, не установщик
и не готовый выпуск для клубов. GUI, драйвер, CA, конфигурация, учётные данные
и диагностические отчёты в архив не входят. Сборка ничего не устанавливает
и не запускает службу; WinDivert gate вызывает только пользовательский DLL
compiler/evaluator, без открытия драйвера.

## Происхождение и проверка

`manifest.json` содержит точный `source_commit`, `build_sequence` из полной
истории Git, версию Go, платформу и SHA256 исполняемого файла. Линкер передаёт
тот же sequence в службу. `build-info.txt` сохраняет результат `go version -m`
без пути временного каталога. `SHA256SUMS` покрывает четыре остальных файла.
Контрольные суммы обнаруживают повреждение файлов, но не заменяют подпись
издателя: скачивайте архив из проверенного запуска репозитория buzzmean/veliq.

CI собирает службу отдельно в Windows PowerShell 5.1 и PowerShell 7,
сравнивает SHA256, сверяет метаданные с checkout и публикует один результат.
Для локальной сборки нужны Windows x64, Git с полной историей и Go 1.25.x.
В корне чистого checkout, в обычном PowerShell, без прав администратора:

```powershell
& {
    $ErrorActionPreference='Stop'
    $commit=& git rev-parse HEAD
    if ($LASTEXITCODE -ne 0) { throw 'GIT_HEAD_FAILED' }
    & .\tools\windows\package-r1-service.ps1 -ExpectedCommit $commit
}
```

Результат появится в `bin\r1-service`; существующий каталог не перезаписывается.
Можно указать другой новый каталог через `-OutputDirectory`. Отсутствующая
закреплённая WinDivert DLL скачивается в `.e2e\windivert` и проверяется по pin;
системный драйвер не меняется. Незакоммиченные tracked-изменения, shallow checkout,
несовпадающий SHA и пользовательские `GOFLAGS` отклоняются. Untracked-файлы не
блокируют сборку, но могут дать `vcs_modified=true`; CI публикует только `false`.

## Последующая приёмка

Установка выполняется отдельно существующим `tools/windows/update-service.ps1`
с `-ServiceExecutable` на распакованный бинарник и с сохранением штатной установки.
Самостоятельное копирование поверх работающей службы и запуск exe из архива
не являются процедурой обновления. Перед установкой сверяют SHA коммита и
SHA256 exe; после неё — SHA256 установленного файла и готовность службы.
Этот архив не даёт разрешения на обновление рабочих ПК.

Windows/WinDivert injection, публичный ISP, холодное воспроизведение YouTube
2160p и Discord voice LOCAL остаются **не проверены этим workflow**. Лабораторные
LOCAL/RELAY bytes не являются измерением экономии на реальном YouTube.
План замеров — `docs/YOUTUBE_LOCAL_FIRST.md` того же коммита. Приёмка R1 и rollout
требуют отдельных результатов; наличие артефакта их не подтверждает.
