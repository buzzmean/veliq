# Пробные сутки и первая личная покупка: тестовый стенд

Рабочее включение этой функции не выполняется. Новые настройки сервера
`PersonalTrials`, `PersonalFirstPurchase`, `PersonalOptimizationLeases` по
умолчанию выключены. Клиентская настройка
`personal_optimization_lease_stage` тоже выключена по умолчанию.

На изолированном стенде проверяются:

- явный запуск 24 часов, без запуска при регистрации, входе и просмотре;
- одна серверная дата окончания при повторных и параллельных запросах;
- первые 90/180/360 дней за 837,90/1 675,80/3 351,60 ₽, без сложения скидок;
- потеря предложения после первой подтверждённой месячной покупки;
- конкуренция заказов и поздние подтверждения без повторной выдачи срока;
- серверная доступность предложений и видимость на широком и узком экране;
- аренда права новой оптимизации: один держатель, без перехвата чужого права.

Миграция 016 добавляет признаки тестового доступа со значением `false` и
отдельную таблицу аренд. Исторические подписки, места, платежи и аудит не
пересчитываются. Новый тестовый доступ требует клиента с согласованной
поддержкой аренды. Старый формат ответа о подписке сохраняется; расширение
запрашивается отдельным подписанным назначением запроса.

## Браузерная проверка

`TestStagingBrowserAcceptanceServer` существует только в тестовой сборке.
Он создаёт отдельную схему PostgreSQL и обслуживает настоящие API кабинета
и файлы сайта через HTTPS на `127.0.0.1:18327`. Почта и внешний платёжный
провайдер заменены локальными эмуляторами; настоящих писем и списаний нет.
Тестовые управляющие URL `/__fixture/*` отсутствуют в обычном сервере.

Для запуска нужны изолированная PostgreSQL, переменная
`VELIQ_TEST_DATABASE_URL` и каталог `VELIQ_STAGING_BROWSER_DIR`:

```sh
go test ./services/control-plane -run '^TestStagingBrowserAcceptanceServer$' -count=1 -timeout=50m -v
python tests/frontend/trial_offers_staging.py --origin https://127.0.0.1:18327 --output /tmp/veliq-trial-browser
```

Сертификат этого локального тестового HTTPS-сервера принимается только в
одноразовом браузерном контексте проверки. Проверки TLS приложения и
рабочего сайта не меняются. Файл `stop` в каталоге стенда завершает сервер
и удаляет его тестовую схему. Порты кабинета, службы и рабочие ПК не нужны.

## Границы результата

Аренда ограничивает новую оптимизацию на поддерживающем её тестовом клиенте.
Ранее закреплённые TCP-потоки не разрываются. Поэтому проверка двух
контроллеров и серверной аренды не означает доказанную эксклюзивность всего
старого трафика или поддержку старых автономных клиентов. Нативная установка,
реальные оплаты и миграция рабочих прав требуют отдельной приёмки.
