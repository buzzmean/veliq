# Проверка TCP и браузеров на Windows

Захват IPv4 TCP работает рядом с UDP. Сборка и прежний успешный UDP-опыт не подтверждают HTTPS, WebSocket или браузерную авторизацию новой версии.

## Путь TCP

Исходящий SYN сопоставляется с настоящей записью владельца: PID, время создания, путь EXE и полное сочетание адресов. Правила передают новое соединение движку. Разрешённый защищённый канал открывается с mTLS и билетом до отражения SYN локальному TCP-слушателю; сервер должен подтвердить открытие назначения.

При отказе поведение ограничено политикой: разрешённый прямой путь может получить исходный SYN, защищённый — не может. Нагрузка приложения повторно не отправляется. Ответ локального слушателя отражается с исходным назначением. Windows сохраняет ответственность за номера, ACK и повторы TCP; TLS, HTTP/2 и WebSocket проходят без подмены сертификата.

Внутренний слушатель принимает только точные отражённые сопоставления, а не произвольные внешние соединения. Собственные сокеты службы исключены; специальное делегирование локальной стратегии имеет отдельное точное разрешение.

Существующий TCP сохраняет маршрут. При обрыве он завершается, новое соединение получает новое решение в пределах политики. Изменение внешнего IP не является бесшовным переносом. Работа с уже открытыми приложениями описана в [подключении без перезапуска процесса](WINDOWS_HOT_ATTACH.md).

## Ограничения и счётчики

Состояние TCP ограничено 8192 записями. Подготовка и очередь имеют отдельные пределы, описанные в [пакетном открытии](TCP_BURST_AND_REVOCATION.md); действующее соединение не вытесняется ради свободного места. Окна QUIC и два буфера копирования по 32 КиБ ограничены. Завершение освобождает обе стороны.

`captured_packets/bytes` и прямые счётчики относятся к исходным IP-пакетам. TCP-байты релея относятся к успешно скопированной полезной нагрузке потока. Граница `Read` не считается сетевым пакетом. UDP сохраняет семантику датаграмм. Порт 443 не доказывает HTTPS, UDP/443 не доказывает QUIC и успешную работу приложения.

## UDP и большие датаграммы

Малые нагрузки до 1100 байт используют исходное кодирование. Расширенный формат допускает 1101–1472 байта через две канонические DATAGRAM-части с номером пакета, длиной и смещением. Сборка ограничена 64 незавершёнными пакетами сессии, 1472 байтами каждый и сроком две секунды. Допускается перестановка частей; потери не восстанавливаются повтором или FEC. Потеря части означает потерю датаграммы.

Для расширения нужны совместимые клиент и релей: старый сервер не понимает новые части. Это не обещание автоматического согласования с любым старым узлом. Чрезмерная выбранная защищённая датаграмма не отправляется молча напрямую. Фрагменты исходного IPv4, большие пакеты и сквозной MTU требуют отдельной поддержки. Вложенный HTTP/3 на стенде не доказывает качество интернета.

## DNS и IPv6

Системный DNS Windows может принадлежать общей службе, а не браузеру. Его нельзя перенаправлять как все соединения выбранного приложения. Собственный DoH браузера относится к его обычному сокету. Кэш может объяснять отсутствие нового DNS-пакета. Запрос диагностического инструмента не выдаётся за запрос самого браузера.

Для фактического DNS используется штатно очищенный netlog и события резолвера. Приватные журналы не публикуются целиком. Общая гарантия приватности всех системных DNS-запросов не заявляется.

Защищённый транспорт IPv6 не поддерживается полностью. Для сопоставленных выбранных потоков есть отдельные ограничения; они не перенаправляют IPv6 в IPv4 и не доказывают, что приложение само выбрало IPv4. Неизвестный владелец, расширения, фрагменты и существующие соединения имеют оговорённые границы. Отсутствие такого наблюдения не означает отсутствие утечки.

## Подготовка проверки

1. Зафиксировать коммит, версию и фактически установленные файлы, состояние службы, захвата и IPC. Использовать штатное обновление с сохранением идентичности и проверенным возвратом. Не копировать EXE поверх работающей службы.
2. Подготовить отдельно разрешённую контролируемую цель с проверяемым сертификатом. Рабочий VPS, ключи, разрешённые адреса и доверие не меняются автоматически тестовым сценарием.
3. Сохранить согласованный набор настроек и временных профилей, точные пути тестовых EXE и признаки владельца. Общий браузер пользователя не закрывать ради чистоты опыта.
4. После проверки восстановить только принадлежащие сценарию изменения. Перезагрузка, отключение адаптера и завершение пользовательской сессии не выполняются.

## Сквозное доказательство

`acceptance-tcp-web.ps1` проверяет одновременные выбранное и контрольное приложения на одном назначении. Готовность должна включать реальный авторизованный транспорт и подтверждение открытия, а не только оценку пинга. Разогрев отделяется от измерения; отказ не скрывается повтором.

Нужны идентичность процесса, цель, перекрывающееся время, настоящие HTTP/HTTPS/H2/WebSocket-ответы, одноразовое подтверждение назначения и фактический исходящий адрес. Общая таблица маршрутизации должна оставаться прежней. При отказе сохраняются очищенный результат и необходимые локальные доказательства, а не только JSON с надписью успеха.

`acceptance-browser.ps1` использует отдельный профиль браузера. Он не подключается к личным данным. Для HTTPS-фикстуры нужен проверяемый сертификат: допустим заранее разрешённый тестовый CA или публично доверенный сертификат контролируемого имени. Обход ошибок сертификата и принудительное объявление QUIC успешным запрещены.

В TCP-режиме проверяются реальные HTTP, HTTPS/H2 и WSS с доказательством ответа и счётчиками. В режиме QUIC требуется настоящий HTTP/3-ответ вместе с UDP-доказательствами. Alt-Svc и UDP/443 сами по себе этого не подтверждают. Временный CA удаляется только по точному отпечатку собственного тестового сертификата.

## Публичные сайты

Ограниченная серверная тестовая политика может разрешать только контролируемую цель. Тогда отказ обычному сайту не является успешным испытанием браузерного релея. Для разрешения публичных назначений нужна отдельно проверенная серверная политика, сохраняющая mTLS, одноразовые билеты, аудиторию, защиту от повторов и запрет частных/служебных сетей.

Профиль сам по себе не подтверждает выбранный путь. Проверяются действительные адреса, счётчики, запросы и пользовательский результат. Вход в Steam/EA, скачивание карты, загрузка видео и управление в игре — разные стадии; успех одной не заменяет остальные.
