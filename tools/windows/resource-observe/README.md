# Пассивное измерение ресурсов

Утилита читает счётчики **уже запущенных** процессов по явно заданным PID.
Она не ищет и не запускает игры, не подключает хуки/ETW, не меняет маршруты,
приоритеты, службы, питание, драйверы или сетевые адаптеры. Перезагрузка,
выключение и завершение пользовательской сессии запрещены.

Сбор ограничен восемью PID, интервалом 5–60 секунд и длительностью до 15 минут.
По умолчанию измеряется только сам сборщик в течение минуты. Вывод — JSONL в
stdout; ошибки возвращают ненулевой код без печати приватных путей/аргументов.
Для Windows собрать `go build -o resource-observe.exe ./tools/windows/resource-observe`.
Локальный исполнитель передаёт уже проверенные PID через `-pids`, время через
`-duration`, интервал через `-interval`. Только один разрешённый исполнитель
сохраняет результат вне одноразового ПК с размером/SHA256 и проверкой чтения.
Это не разрешение на установку кандидата или переключение VELIQ во время игры.

`known` — маска доступности: CPU=1, WorkingSet=2, Private=4, IO=8, Handles=16,
Threads=32, SystemCPU=64. Поле без соответствующего бита **не измерено**;
его числовой ноль не означает отсутствие нагрузки. `delta.known` применим только
к CPU/IO/SystemCPU. Первое наблюдение, смена PID/birth, потеря источника,
уменьшение счётчика и сбой времени отмечаются явно. `birth` передаётся строкой,
чтобы сохранить точные 64 бита. `cost_ns` — собственное прошедшее время чтения,
а не отдельный измеритель CPU сборщика.

Windows использует query-only handle и прямые API: время процесса, счётчики IO,
рабочий набор/commit, handles и системное время CPU. Потоки Windows оставлены
неизвестными: поддержанный дешёвый источник для одного PID отсутствует, а
глобальный обход потоков не выполняется. На ПК с несколькими processor groups
SystemCPU также неизвестен: `GetSystemTimes` не доказывает нагрузку всего ПК.
Ошибки доступа не считаются доказанным завершением процесса.

Linux поддерживает только собственный процесс: реальный `getrusage` и
ограниченные чтения `/proc/self`. IO Linux отражает storage accounting;
Windows — transfer accounting. Эти значения нельзя напрямую сравнивать между ОС.

`cpu_delta_ns / elapsed_ns` означает использованные CPU-ядра. Это **не FPS** и
не процент всего многопроцессорного ПК. Время кадра и FPS обозначены
`UNKNOWN_NO_FRAME_TIME_SOURCE`. Проверка влияния на FPS требует отдельного
безопасного измерения настоящего frame-time; CPU, RSS и throughput его не заменяют.
